# 规则树交互原型

直接打开 `index.html` 即可运行，无框架、构建工具和后端依赖。

- 主画布所有节点统一为单击选中；规则、条件和动作节点可双击或按 Enter 编辑。右侧只读展示“节点类型 → 类型化摘要 → 可用操作”，不暴露演示用内部 ID，也不维护能从树结构推导出的连线属性。串、并、分展示步骤或分支数量，规则展示规则名称与单一/复合结构，动作展示动作名称与方法标识。
- 串、并、分、动作等可折叠流程节点在下方显示 `−`，点击收起后变为 `+`，再次点击展开；规则节点的命中流程保持在主画布原位展示。
- 主画布只展开 `Flow` 递归；`JNode` 与其规则子树统一投影为一个规则节点，不展示可能很长的 DSL 或条件摘要。命中流程保持在节点正下方，纯 `Rule` 子树不再占用画布空间。
- 简单规则和复合规则使用同一个节点与弹窗：简单规则表示为 `JNode(RNode, Flow?)`，复合规则表示为 `JNode(LNode/HNode, Flow?)`。两者的区别只在弹窗内规则树根节点的复杂度，主画布不再提供独立的简单条件创作入口。
- 双击规则节点或点击右侧“编辑规则”，会在一个独立弹窗中展示完整规则树；选择、属性修改、增加和删除规则都在同一弹窗内完成，不会继续打开第二层弹窗。动作和旧 `CNode` 通过独立的取消/保存弹窗编辑；串、并、分等结构节点没有额外可编辑属性，因此不提供空的编辑入口。
- 节点别名属于 `JNode.rule` 指向的实际规则根节点，不属于外层 `JNode`，也不属于后台规则定义。单一 `RNode` 有别名时显示别名，未设置时显示所引用的后台规则名称；复合 `LNode/HNode` 有别名时显示别名，未设置时显示“复合规则”。所有情况都不会回退展示表达式。
- `SNode`、`PNode`、`DNode` 在主画布统一投影为“串、并、分”三个圆形行为模型；这些简称只用于画布图形，属性区统一按节点类型显示“串行、并行、分支”，结构节点不保存额外名称。其中“分”表示按顺序检查并只命中一个的有序互斥分支，可带默认分支。
- 规则弹窗按从左到右布局：父规则位于左侧，子规则向右递归，同级规则纵向排列；主画布流程仍按从上到下布局。
- 其他节点的悬停工具栏支持新增子节点、同级节点和删除。
- 新增入口会按 `next`、`action`、`branches`、`rule` 等真实递归边限制可选节点类型和数量；新建串、并、分时不要求填写模型中不存在的名称或 DSL。
- 编辑器仍可渲染已有 `CNode` 数据，但新建业务规则统一生成 `JNode`，使简单规则后续可以在同一个规则域内扩展为与、或或 `hits` 组合。
- 新建 `JNode` 后直接进入规则弹窗。原子规则只能从模拟后端 `RuleDefinition` 的下拉框选择，不能手填或临时创建；演示数据只暴露 `ruleId`、`desc`、`useType`，其中 `RNode.expression` 对应实际 JSON 的 `RNode.expr`，保存 `ruleId` 引用。节点别名独立保存，未设置时回退显示后台规则名称。
- 添加入口先选择一条已有规则，可继续增加规则；只有选择两条及以上规则时才选择“与”或“或”组合方式。
- 规则弹窗右侧默认处于查看态，全部字段只读；点击“编辑”后显示并排的“取消 / 保存”按钮，并按节点类型开放引用规则、与/或类型、命中表达式或节点别名。保存一次性提交草稿并恢复查看态，取消直接丢弃；存在未保存修改时，切换节点、关闭弹窗或执行结构操作会先确认。右键菜单中的“编辑”复用右侧编辑态，不再打开第二套编辑浮层。
- 前插或后插只打开一个规则列表面板：默认一条规则，点击“添加规则”继续增加；一条时生成原子规则，两条及以上才显示与/或并生成包含全部所选规则的组合，删除回一条时自动退化。新增规则始终相对当前节点插入到同级的之前或之后，名称创建后再单独编辑。
- 任意 `RNode` 的右键菜单都提供“添加规则”：当前规则固定为第一条，可继续增加多条后台规则，并在底部选择“与/或”。保存后新建一个未命名 `LNode` 包裹当前规则和全部新增规则，既支持根规则，也支持组合内部的原子规则；不再暴露“转为复合规则”术语。已有 `HNode` 保持兼容，但当前入口不新建 `hits`。
- 拖动画布可平移；滚轮平移；`Ctrl/Command + 滚轮` 或顶部按钮缩放。
- “适应画布”会在节点增删、折叠后重新计算可视区域。

该页面只验证交互和递归布局，数据保存在浏览器内存中，不改变 `mousika-ui` 作为树结构适配层的模块定位。
