# 规则树交互原型

直接打开 `index.html` 即可运行，无框架、构建工具和后端依赖。

- 主画布所有节点统一为单击选中，不提供悬浮新增、编辑或删除入口；双击条件节点会打开规则弹窗，其余节点双击无操作，主画布不用 Enter/Delete 直接改结构。右侧栏使用独立卡片展示，标题固定为“节点属性”，节点类型以标题右侧标签显示；条件、动作、串行、并行和分支节点都可以设置可选的“节点名称”，未设置时不生成该字段。节点名称和后台规则引用通过字段旁的轻量编辑入口就地修改，新增流程也在当前卡片内完成，不再为普通流程属性叠加弹窗。可删除节点的删除入口统一弱化放在卡片底部，点击后通过页面模态弹窗确认，根节点不生成删除入口。操作按节点实际持有的递归边提供，不暴露演示用内部 ID，也不维护能从树结构推导出的连线属性。
- 主流程页面只展示六类用户可理解的节点类型：根节点、并行节点、串行节点、分支节点、条件节点和动作节点。`ROOT/P/S/D/J/C/A` 等内部 JSON 类型标识不进入页面文案；`JNode` 与兼容的 `CNode` 在主流程中都显示为条件节点。
- 主画布只保留折叠交互：串、并、分、动作等可折叠流程节点在下方显示 `−`，节点与折叠按钮之间保留独立间距以避免误触；点击收起后变为 `+`，再次点击展开。右侧栏不再重复提供折叠按钮，规则节点的命中流程保持在主画布原位展示。
- 主画布只展开 `Flow` 递归；`JNode` 与其规则子树统一投影为一个规则节点，不展示可能很长的 DSL 或条件摘要。命中流程保持在节点正下方，纯 `Rule` 子树不再占用画布空间。
- 简单规则和复合规则使用同一个节点与弹窗：简单规则表示为 `JNode(RNode, Flow?)`，复合规则表示为 `JNode(LNode/HNode, Flow?)`。两者的区别只在弹窗内规则树根节点的复杂度，主画布不再提供独立的简单条件创作入口。
- 双击条件节点，或选中后点右侧“查看规则”，会打开独立规则弹窗；弹窗左侧展示完整规则树，右侧是常驻的直接编辑面板。选中某个规则节点后即可就地编辑：逻辑节点切换“与/或”并对直接子规则排序，组合节点通过“添加规则”增补子规则，任意规则可删除，改动实时反映到规则树。没有“查看/编辑”切换，也没有规则节点右键菜单。动作和兼容 `CNode` 的后台规则引用直接在主画布右侧栏修改。
- 条件节点的页面节点名称仍属于 `JNode.rule` 指向的实际规则根节点，不属于外层 `JNode`，也不属于后台规则定义。单一 `RNode` 有名称时显示名称，未设置时回退显示所引用的后台规则；复合 `LNode/HNode` 有名称时显示名称，未设置时显示“复合规则”。所有情况都不会回退展示表达式。
- `SNode`、`PNode`、`DNode` 在主画布统一投影为“串、并、分”三个圆形行为模型；这些简称只用于画布图形，属性区统一显示“串行节点、并行节点、分支节点”。结构节点与条件、动作节点一样可以设置可选节点名称，但名称不替代节点类型。其中“分”表示按顺序检查并只命中一个的有序互斥分支，可带默认分支。
- 规则弹窗按从左到右布局：父规则位于左侧，子规则向右递归，同级规则纵向排列；主画布流程仍按从上到下布局。
- 右侧栏不再提供泛化的“子节点 / 同级节点”操作。“同级”不是当前节点持有的模型字段，新增操作只作用于选中节点自身的真实递归边：根节点设置流程入口，动作节点设置 `next`，判断节点设置命中 `action`，串行/并行节点追加 `branches`，决策节点添加有序条件分支或设置默认分支。
- 所有引用后台定义的字段统一称为“引用规则”。动作和兼容条件节点直接展示所引用的后台规则；判断节点展示原子引用或复合规则摘要，不在右侧重复展示命中流程。动作仅在已有后继时展示下一步，没有后继时提供“添加下一步”。串行、并行和分支节点统一展示“分支数”并提供“添加分支”，分支节点另外展示默认分支状态。
- 新增入口会按 `next`、`action`、`branches`、`rule` 等真实递归边限制可选节点类型和数量。添加流程分支时先选择节点类型；条件节点和动作节点再通过“引用规则”从模拟后端定义中选择，不手填规则表达式。已有直接子节点时，可选择相对某个子节点前插或后插；决策节点的默认分支不作为条件分支的插入参照。节点名称创建后可在编辑入口按需设置，删除操作不得留下空的串行、并行或决策结构。
- 编辑器仍可渲染已有 `CNode` 数据，但新建业务规则统一生成 `JNode`，使简单规则后续可以在同一个规则域内扩展为与、或或 `hits` 组合。
- 新建 `JNode` 后直接进入规则弹窗。原子规则只能通过“引用规则”从模拟后端 `RuleDefinition` 中选择，不能手填或临时创建；演示数据只暴露 `ruleId`、`desc`、`useType`，其中 `RNode.expression` 对应实际 JSON 的 `RNode.expr`，保存 `ruleId` 引用。节点名称独立保存，未设置时回退显示后台规则描述。
- 添加入口先选择一条已有规则，可继续增加规则；只有选择两条及以上规则时才选择“与”或“或”组合方式。
- 规则弹窗采用事务化保存：打开时对该判断节点的规则子树做深拷贝快照。面板内的改动（切换与/或、排序、增删子规则、配置根规则）会即时写入规则树做实时预览，但只有点弹窗顶部“保存”才真正提交到主画布模型并关闭；“取消”或 Esc 丢弃全部改动并回滚到快照。
- 配置根规则或向组合规则“添加规则”时用一个规则列表面板：默认一条规则，点“添加规则”继续增加；只选一条生成原子 `RNode`，选两条及以上才出现“与/或”并生成包含全部所选规则的 `LNode`，删除回一条时自动退化为该原子规则。新增子规则追加到组合末尾，顺序再通过拖拽或行内 ↑↓ 调整，名称创建后再单独编辑。
- 复合规则（与/或）只在配置根规则或向已有组合“添加规则”时产生：选两条及以上即生成未命名 `LNode`。当前面板不提供把单个已存在的原子规则就地“转复合”，也不新建 `hits`；已有 `HNode` 数据仍可正常渲染与保存。
- 规则弹窗里选中任意规则节点都可切换“取反”，对该规则整体取“非”（对应后端 `isNegative`）。取反的节点在规则树和主画布条件节点上都会显示红色“非”标记；改动同样走事务化保存（“保存”提交、“取消”回滚）。
- 主画布与规则弹窗都支持同父兄弟拖拽重排：只在同一父节点、同一有序分组内换序（串/并的分支、分支节点的条件分支、逻辑/命中节点的子规则），不改父、不改数量、不改语义。拖拽时用虚线占位卡加光标标签提示落点，落回自身原槽视为无效不改动；原有下拉框放置和行内 ↑↓ 排序保留。
- 拖动画布可平移；滚轮平移；`Ctrl/Command + 滚轮` 或顶部按钮缩放。
- “适应画布”会在节点增删、折叠后重新计算可视区域。

该页面只验证交互和递归布局，数据保存在浏览器内存中，使用统一的 `{type, relation, expression, children}` 结构，并不与后端真实 UI JSON（`next` / `action` / `branches` / `rule` / `rules` / `expr`、`HNode` 的 `minHits`+`maxHits` 等）双向映射，也不执行 “UI → JSON → UI → Rule” 往返校验；它是交互与布局原型，不改变 `mousika-ui` 作为树结构适配层的模块定位。
