# 前端一致性整改清单

## 统一原则

- 节点由自身配置和递归关系组成
- 自身配置完整后才创建真实节点
- 必需递归关系缺失时显示虚拟插槽，并阻止保存、测试和发布
- 相同拓扑节点共享添加、折叠、删除和编辑逻辑
- 画布、右栏和右键菜单读取同一份节点能力定义
- 结构、条件和动作样式只读取设计令牌

## 问题与方案

| 编号 | 问题 | 统一方案 | 方案评审 |
| --- | --- | --- | --- |
| FE-01 | 节点类型能力在添加、编辑、右键和删除逻辑中重复判断 | 新增无 DOM 依赖的节点能力模块，集中声明自身配置、递归关系、最少数量、操作文案和允许类型 | 合理，直接消除新增节点时的多点修改，不引入业务无关抽象 |
| FE-02 | 条件节点与动作、循环同为单分支节点，却被排除在折叠能力之外 | 所有存在执行子节点的流程节点统一支持折叠 | 合理，折叠只影响展示，不改变条件语义 |
| FE-03 | 虚拟插槽与保存校验分别维护约束，循环条件没有复用条件完整性规则 | 虚拟插槽、节点自身校验和完整性校验共同读取能力定义，循环条件复用条件节点校验 | 合理，可保证画布提示、节点配置与保存结果一致 |
| FE-04 | 单规则提升为复合规则时节点数和深度按纯新增计算 | 按替换一个节点计算，并从旧节点父级计算新增深度 | 合理，符合实际树结构变化 |
| FE-05 | 组合规则类型判断散落在多处，条件与、条件或支持右栏排序按钮，限定匹配只支持画布拖拽 | 集中声明规则编辑能力，三种组合规则统一提供拖拽和上下移动入口 | 合理，三者共享同一有序子规则集合 |
| FE-06 | 内部操作混用自定义确认框和浏览器原生确认框 | 编辑器和控制台页面内确认统一使用自定义确认框，仅保留浏览器关闭时的原生 `beforeunload` | 合理，浏览器关闭提示无法由页面弹窗可靠替代 |
| FE-07 | 删除按钮保留永远不会出现的禁用提示 | 非根节点统一允许删除，缺失必需关系由虚拟插槽和完整性校验处理 | 合理，符合允许编辑中间态但禁止保存不完整结构的规则 |
| FE-08 | 编辑器节点样式存在前后两套定义，语义颜色绕过令牌 | 合并为一套节点样式，结构、条件、动作及选中态使用语义令牌 | 合理，保留现有形状和尺寸，只收敛编辑器节点的颜色来源，不扩大到控制台业务页面重构 |
| FE-09 | 同一公共资源在不同页面使用不同缓存版本 | 所有本地静态资源统一使用同一发布版本 | 合理，可避免页面命中不同历史缓存 |
| FE-10 | 缺少可执行的前端节点约束测试 | 使用 Node 内置测试覆盖能力、关系、必需插槽和完整性规则，并保留实际浏览器冒烟检查 | 合理，不增加 npm 依赖即可保护核心交互契约 |
| FE-11 | 编辑器文档仍把 Loop 写成独立 `condition/action` 结构，并称草稿允许不完整节点 | 按现有 `FlowNode(rule,next)` 模型和前端完整性约束更新文档 | 合理，避免后续实现重新引入已删除的特殊模型 |
| FE-12 | 新增组合规则时只有条件与和条件或，无法直接创建限定匹配节点 | 根规则与子规则构建器统一支持条件与、条件或、限定匹配，限定匹配共用现有范围校验 | 合理，创建和后续编辑使用相同的三种组合语义 |
| FE-13 | 条件配置弹窗使用多层横线划分区域，视觉层级过重 | 去掉头部、画布标题和右栏内部横线，以背景明度和留白区分画布与属性区 | 合理，保留必要控件边界且不削弱信息分区 |
| FE-14 | `MatchNode` 在节点类型、创建入口和属性字段中混用“命中数量”“命中”和“命中要求” | 节点类型统一为“限定匹配”，数量属性统一为“匹配数量” | 合理，节点名称表达规则语义，字段名称表达配置内容 |
| FE-15 | 根规则、追加子规则和提升为组合规则分别维护构建状态与渲染逻辑，参数能力不一致 | 三个入口统一使用同一规则构建器状态、行渲染、操作符选择和提交逻辑 | 合理，入口只保留模式差异，规则参数和校验能力完全一致 |
| FE-16 | 节点名称、画布缩写、帮助文案和规则操作符选项同时硬编码在 JavaScript 与 HTML | 节点展示元数据统一由 `flow-design.js` 的能力定义提供，规则操作符统一由 `RULE_OPERATORS` 提供 | 合理，画布、右栏和弹窗读取同一来源 |
| FE-17 | 控制台页面重复声明顶栏、按钮、表格、弹窗、提示和状态开关基础样式 | 基础控件样式统一放入 `ui-common.css`，各页面只保留自身布局和业务状态差异 | 合理，公共视觉规则集中维护，页面差异仍清晰可见 |
| FE-18 | 场景、规则和函数列表分别处理请求竞态、加载、异常和页码回退 | 使用 `createPagedTable()` 统一分页请求状态机，页面只提供查询参数和行渲染 | 合理，消除行为漂移且不耦合业务列结构 |

## 验收标准

- 新增节点类型时，交互能力和约束只需在一个模块声明
- 条件、动作和循环存在后续时均可折叠
- 画布必需插槽和保存校验不存在规则差异
- 条件与、条件或、限定匹配的子规则操作一致
- 条件与、条件或、限定匹配均可在创建时直接选择
- 根规则、追加子规则和提升为组合规则使用同一构建逻辑并支持规则参数
- 页面内不再直接调用 `window.confirm`
- 节点语义色不再由文件末尾覆盖块修正
- 节点展示名称和规则操作符没有 HTML 硬编码副本
- 控制台公共控件样式只在 `ui-common.css` 中定义
- 场景、规则和函数列表使用同一分页请求状态机
- 所有页面公共资源版本一致
- JavaScript 语法检查、Node 前端测试和 Web 模块测试通过

## 实施状态

- FE-01 至 FE-18 已按上述方案实施
- 浏览器关闭仍使用原生 `beforeunload`，其余页面内确认均使用统一确认框
- 控制台各业务页面保留自身布局和业务状态样式，公共控件样式由 `ui-common.css` 提供

## 循环复查

- 第一轮实施后发现判断节点仍有一处重复选中样式，已合并
- 浏览器检查确认条件、动作、循环均按执行子节点统一折叠，终止动作不显示虚拟后续
- 第二轮发现组合规则类型判断仍有重复，已收敛到规则编辑能力定义
- 第二轮发现循环条件只判断对象存在，已改为复用条件完整性校验
- 第三轮发现组合规则创建入口缺少限定匹配，且条件弹窗横线层级过重，已统一创建语义并收敛分隔样式
- 第四轮统一 `MatchNode` 的节点名称和匹配数量字段文案
- 第五轮合并三个组合规则构建入口，统一节点和操作符元数据、控制台基础样式及分页请求状态机
- 第五轮复查发现控制台仍有三处原生确认框，已统一改用公共确认弹窗
- 再次执行静态检查、前端约束测试、Web 测试与浏览器交互检查，未发现新的不一致
