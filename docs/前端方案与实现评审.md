# 前端交互方案与实现评审

评审对象：`flow-design.js` 节点能力模型、`app.js` 交互实现、规则编辑器页面、控制台公共组件和 FE-01～18 整改结果

## 总体结论

当前方案与代码采用同一套模型：编排节点由自身配置和递归关系组成，自身配置完整后才创建真实节点，未补全的必需递归关系只显示为虚拟插槽。虚拟插槽不进入 UI AST，不参与序列化；保存草稿、测试和发布均要求必需关系完整

Claude 原评审提出的三处冲突中，只有串行和并行最少子节点数的观察成立，但应以当前产品约束为准更新文档。其余两项与已确认方案不符，不应据此修改代码

## 已确认的交互约束

### 节点创建与完整性

- 动作节点在创建弹窗中必须选择动作规则
- 条件节点在创建弹窗中必须配置完整判断条件
- 循环节点在创建弹窗中必须配置最大循环次数和循环条件
- 串行、并行和分支节点没有额外必填属性，创建后由虚拟插槽表达尚未建立的递归关系
- 取消创建不生成真实节点，也不改变草稿
- 必需递归关系缺失时禁止保存草稿、测试和发布

### 递归关系

- 动作节点和条件节点的 `next` 为可选后续流程
- 循环节点的 `next` 为必需循环体
- 串行节点至少包含两个步骤
- 并行节点至少包含两个分支
- 分支节点至少包含一个条件分支和一个默认分支，条件分支始终显示在默认分支左侧
- 虚拟插槽由 `flow-design.js` 的关系定义生成，不写入 `TreeNode` JSON

### 编辑、转换与删除

- 画布、右栏和右键菜单统一读取 `flow-design.js` 中的节点能力
- 串行和并行节点支持互相转换，其他结构变化通过插入节点完成
- 动作、条件和循环是单分支直通节点；存在合法后续时可仅删除当前节点并将后续提升到当前位置
- 删除单分支节点时也可选择删除当前节点及其后续
- 串行、并行和分支等多分支节点只支持删除整棵子树
- 条件与、条件或和限定匹配共享子规则新增、排序、删除及类型转换能力

## Claude 评审意见复核

| 原意见 | 复核结论 | 当前口径 |
| --- | --- | --- |
| 草稿应允许保存不完整结构 | 不采纳 | 节点为空或必需递归关系未补全时禁止保存草稿 |
| 串行和并行的最少子节点数存在文档冲突 | 采纳文档修正 | Web 编辑器统一要求至少两个子节点 |
| 删除应始终删除整棵子树 | 不采纳 | 单分支直通节点支持仅删除当前节点，多分支节点只删除整棵子树 |
| Loop 需要核对 UI 到 Core 的字段映射 | 已核对 | UI `LoopNode(max, rule, next)` 对应 Core `loop(max, condition, action)` |
| 虚拟节点可能污染语义树 | 已核对 | 虚拟插槽只由视图层生成，序列化仅遍历真实节点 |

## 命名规范

- `LogicNode(expr="&&")`：条件与
- `LogicNode(expr="||")`：条件或
- `MatchNode(expr="some")`：限定匹配
- `MatchNode.minHits/maxHits`：匹配数量、最少匹配、最多匹配
- `LoopNode`：循环节点
- 画布结构节点可使用“与”“或”“限”“循”等单字缩写

## 实现复核

- `flow-design.js` 集中声明节点配置类型、递归关系、最少数量、直通能力和可转换类型
- 节点名称、画布缩写和帮助文案由同一能力定义提供，条件与、条件或和限定匹配选项由 `RULE_OPERATORS` 提供
- `requiredRelations()` 同时驱动画布虚拟插槽和完整性校验
- `saveToBackend()`、试运行和发布均执行完整性与规则参数校验
- `canDeleteCurrentOnly()` 只允许具有合法后续的单分支直通节点提升后续
- 规则编辑器将 `LogicNode` 与 `MatchNode` 视为同类组合规则，统一编辑子规则
- 根规则、追加子规则和提升为组合规则共用同一构建器，规则参数、范围校验和提交逻辑一致
- 场景、规则和函数列表共用 `createPagedTable()` 处理竞态、加载、异常和页码回退
- 控制台基础控件样式由 `ui-common.css` 提供，页面文件只维护自身布局与业务状态差异
- 页面内确认使用统一弹窗，浏览器关闭场景保留原生 `beforeunload`

## 验证范围

- Node 测试覆盖节点能力、必需递归关系、完整性、分支约束、转换和组合规则能力
- Web 集成测试覆盖页面资源、循环节点入口、限定匹配创建入口、规则流保存发布与执行路径
- UI AST 测试覆盖循环节点 JSON 往返、嵌套及 DSL 编译

在上述范围内，文档、前端约束和现有实现一致
