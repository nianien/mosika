# UI 树与 Web 规则编辑器

> 适用模块：`mosika-ui`、`mosika-web`
>
> 更新时间：2026-08-13

## 1. 职责边界

`mosika-ui` 只提供可序列化、可递归遍历的 UI AST，以及 UI AST 到内核 `RuleNode` 的单向编译。它不包含页面、布局或 Web 依赖。

`mosika-web` 是参考控制面，负责命名空间、原子规则、JavaScript UDF、业务场景、版本和 UI AST 的管理，并提供 REST、SQLite 持久化与静态页面。

UI AST 及其 JSON 是编辑和持久化的事实来源。执行树只保留运行语义，不能从 `RuleNode` 或 DSL 反向恢复 UI 布局和编辑元数据。

## 2. 两个递归域

当前 UI AST 以 `Flow` 为宿主，以 `Rule` 为嵌入式子语言：

```text
Tree = T(Flow)

Flow = A(rule, next?)
     | C(rule, next?)
     | S(Flow+)
     | P(Flow+)
     | D(C+, default?)

Rule = R(expr, args?)
     | B(expr, args?, negative)
     | L(and | or, Rule+)
     | H(minHits, maxHits, Rule+)
```

两个域只通过 `FlowNode.rule -> RuleNode` 单向连接：

- `ANode.rule` 是动作规则引用，`next` 是无条件后继；
- `CNode.rule` 是条件规则树，`next` 是命中后的流程；
- `RuleNode` 不能引用 `UINode`，因此规则表达式不会反向携带流程关系。

## 3. 节点契约

| JSON 类型 | Java 节点 | 递归边 | 约束与语义 |
| --- | --- | --- | --- |
| `T` | `TreeNode` | `next` | 序列化根；`next` 是整棵流程的唯一入口 |
| `A` | `ANode` | `rule`、`next` | 绑定动作规则；执行完成后进入可选后继 |
| `C` | `CNode` | `rule`、`next` | 绑定条件规则树；命中后进入可选流程 |
| `S` | `SNode` | `branches` | 一个或多个流程子树，严格按顺序执行 |
| `P` | `PNode` | `branches` | 一个或多个流程子树，并发执行并等待全部完成 |
| `D` | `DNode` | `branches`、`defaultBranch` | 有序检查 `CNode`，命中首个后停止；全部未命中时进入可选默认流程 |
| `R` | `RNode` | 无 | 原子规则引用，可携带模板参数 |
| `B` | `BNode` | 无 | 可取反的原子条件规则 |
| `L` | `LNode` | `rules` | 与/或组合，至少两个规则子节点 |
| `H` | `HNode` | `rules` | `some` 命中数量组合，边界必须合法 |

`DNode` 至少形成两个结果出口，即条件分支数量加默认分支数量不小于二。条件分支的 `next` 可以为空：命中后停止检查，但不执行额外动作。默认分支不能是另一个裸 `CNode`。

所有节点统一继承 `NameNode.name` 作为展示名称，不存在独立 `label` 字段。名称不参与编译和求值。

树在递归校验、编译和序列化前执行规模预检：最大深度 128，节点总数 2000，并拒绝重复对象引用和循环引用。这是编辑器与服务端共同执行的结构预算，不是 DSL 业务语义。

## 4. 单向编译

```text
UI TreeNode JSON
      │ deserialize / validateSize
      ▼
   TreeNode
      │ validate / UINodeAdapter.toRule()
      ▼
   RuleNode
      │ expr / RuleDefinition(ruleType=2)
      ▼
   RuleSuite
```

`UINodeAdapter` 只保留执行语义：

- `name`、选择状态和折叠状态不进入执行树；
- `RNode.expr` 保存稳定 `ruleId` 引用，不复制后台 JavaScript 表达式；
- `SNode/PNode` 编译为显式串行/并行结构；
- `CNode` 编译为条件规则及其可选命中流程；
- `DNode` 编译为按顺序嵌套的 `CaseNode`；
- 业务场景引用以 `f<id>` 存在普通 `ANode.rule.expr` 中，不引入独立调用节点；
- 不提供从执行树返回 UI AST 的逆向转换。

修改节点模型时必须同步检查 `UINodeAdapter.toRule()`、`TreeNode.visit()`、`NodeTypeResolver`，以及“UI -> JSON -> UI -> Rule”的结构和执行语义。

## 5. 主画布投影

- 主画布只展开 `Flow` 递归，显示根、串行、并行、决策、条件和动作节点；
- `SNode`、`PNode`、`DNode` 分别显示为“串”“并”“分”，“分”表示有序互斥决策；
- `CNode` 与其规则子树在主画布合并为一个条件节点，规则树不占用主画布空间；
- 条件命中流程继续在 `CNode.next` 下方展开，不通过嵌套弹窗表达流程；
- 布局、折叠、缩放和连线方向只服务阅读，不参与执行语义。

主画布单击选中节点。普通属性在右侧面板编辑；新增操作只作用于节点真实持有的 `next`、`branches` 或 `defaultBranch`。

## 6. 条件规则弹窗

双击条件节点或点击“查看规则”打开条件规则弹窗：

- 左侧从左到右展开纯 `Rule` 子树，同级规则纵向排列；
- 右侧为常驻编辑面板；
- 一条规则引用使用原子条件节点，多条引用可以组合为与/或；
- 原子条件可以设置模板参数和取反；
- 已有 `HNode` 可以显示和保存，当前与/或转换入口不新建 `some`；
- 规则子节点可以在同一父节点内排序。

弹窗打开时保存规则子树快照。面板修改实时更新预览，但只有“保存”才提交；“取消”或 Esc 恢复快照。外层 `CNode`、`CNode.next` 和主流程位置不因规则编辑而被替换。

## 7. 名称与引用

- 所有 UI AST 节点的可选展示名称统一使用 `name`；
- 条件画布节点名称来自 `CNode.name`，内部规则名称来自 `CNode.rule.name`；
- 原子规则未命名时回退显示所引用的后台规则描述；
- 动作节点只能引用动作类型原子规则或业务场景；
- 条件节点只能引用条件类型原子规则；
- 新引用必须来自同一命名空间内当前可用的定义。

## 8. 排序与画布操作

- 主画布和条件规则弹窗只允许同一父节点、同一有序分组中的兄弟重排；
- 排序只改变列表顺序，不改变父节点、分支数量或节点类型；
- 画布支持节点折叠、拖拽平移、滚轮平移、`Ctrl/Command + 滚轮` 缩放和“适应画布”；
- `CNode.next` 属于主流程递归，不能放进条件规则弹窗中导航。

## 9. 草稿、发布与版本

每个业务场景拥有稳定 `flowId` 和递增业务版本：

- 新建场景生成版本 `1` 的草稿；
- 草稿可直接编辑和保存，保存时只要求 JSON 可反序列化且不超过规模预算，允许保留尚未完成的结构；
- 发布对草稿执行完整结构校验、单向编译、规则引用类型和命名空间校验；
- 发布成功后该版本成为当前发布版本，原当前发布版本转为历史版本，并刷新运行态 `RuleSuite`；
- 当前发布版本、历史版本和停用版本均为只读，不能直接保存；
- 点击“修改”会基于当前查看版本创建新的草稿版本，再进入编辑；
- 本地未保存修改只表示编辑器脏状态，不等同于后端草稿状态；
- 导入、保存或发布失败时整体拒绝，不部分替换当前树。

编辑期内部 ID、选中和折叠状态不持久化。后端存储规范化 `TreeNode` JSON，并在发布时收集动作、条件和业务场景引用。

## 10. 页面入口

- `/`：产品首页，展示 Core、UI AST 与参考控制面的技术边界
- `/namespaces`：命名空间选择与管理
- `/scenes`：当前命名空间的业务场景与版本入口
- `/rules`：原子规则库
- `/udfs`：JavaScript UDF 注册中心
- `/flow/{flowId}`：指定业务场景的规则树编辑器
- `/ui/*.html`：Spring Boot 暴露的静态页面源入口
