# UI 树与 Web 规则编辑器

> 适用模块：`mosika-ui`、`mosika-web`

## 1. 职责边界

`mosika-ui` 提供可序列化、可递归遍历的 UI AST，以及 UI AST 到内核 `RuleNode` 的单向编译。它不包含页面、布局和 Web 依赖。

`mosika-web` 是参考控制面，负责命名空间、原子规则、JavaScript UDF、业务场景、版本和 UI AST 的管理，并提供 REST、SQLite 持久化与静态页面。

UI AST 及其 JSON 是编辑和持久化的事实来源。执行树只保留运行语义，不能从 `RuleNode` 或 DSL 反向恢复 UI 布局和编辑元数据。

## 2. 模型结构

当前模型把类型识别、节点命名、执行拓扑和规则表达式分开：

```text
TypeNode
└─ NameNode(name)
   ├─ TreeNode(next)
   ├─ UINode
   │  ├─ FlowNode<R extends RuleNode>(rule, next)
   │  │  ├─ ANode<RNode>
   │  │  └─ CNode<BNode>
   │  └─ BranchNode<N extends UINode>(branches)
   │     ├─ DNode<CNode>(defaultBranch)
   │     ├─ SNode<UINode>
   │     └─ PNode<UINode>
   └─ RuleNode
      └─ RNode(expr, args)
         └─ BNode(negative)
            └─ LNode(rules)
               └─ HNode(minHits, maxHits)
```

模型包含两个递归域：

```text
Flow = A(rule, next?)
     | C(rule, next?)
     | S(Flow+)
     | P(Flow+)
     | D(C+, default?)

Rule = R(expr, args?)
     | B(expr, args?, negative)
     | L(and | or, Rule+)
     | H(minHits, maxHits, Rule+)
```

两个递归域只通过 `FlowNode.rule -> RuleNode` 单向连接。规则节点不能引用 `UINode`，因此规则表达式不会反向携带流程关系。

## 3. 节点与字段

| JSON 类型 | Java 节点 | 自有递归边 | 语义 |
| --- | --- | --- | --- |
| `T` | `TreeNode` | `next` | 序列化、遍历、校验和编译入口 |
| `A` | `ANode` | `rule`、`next` | 执行动作规则，再执行可选后继 |
| `C` | `CNode` | `rule`、`next` | 判断条件规则，命中后执行可选流程 |
| `S` | `SNode` | `branches` | 按顺序执行完整流程子树 |
| `P` | `PNode` | `branches` | 并发执行完整流程子树并等待完成 |
| `D` | `DNode` | `branches`、`defaultBranch` | 有序检查条件分支，命中首个后停止 |
| `R` | `RNode` | 无 | 规则引用，可携带模板参数 |
| `B` | `BNode` | 无 | 可整体取反的规则引用 |
| `L` | `LNode` | `rules` | 与或组合 |
| `H` | `HNode` | `rules` | `some` 命中数量组合 |

字段归属如下：

| 字段 | 所属类型 | 含义 |
| --- | --- | --- |
| `name` | `NameNode` | 展示名称，不参与编译和求值 |
| `rule` | `FlowNode` | 动作或条件绑定的规则表达式 |
| `next` | `FlowNode`、`TreeNode` | 单出口关系，具体语义由节点类型决定 |
| `branches` | `BranchNode` | 有序的完整流程子树 |
| `defaultBranch` | `DNode` | 条件均未命中时执行的默认流程 |
| `expr`、`args` | `RNode` | 规则引用和模板参数 |
| `negative` | `BNode` | 是否对整个规则表达式取反 |
| `rules` | `LNode` | 有序子规则列表 |
| `minHits`、`maxHits` | `HNode` | 命中数量范围 |

`BranchNode` 不拥有 `rule` 或 `next`。组合结构需要与后续子树串联时，由外层 `SNode` 表达。

`LNode` 和 `HNode` 通过继承复用可取反语义，但不使用继承得到的原子调用参数。模板参数只由叶子 `RNode`、`BNode` 生成到规则 DSL 中。

## 4. 遍历与校验

`TreeNode.visit()` 按以下关系遍历执行树及其嵌入的规则树：

```text
TreeNode   -> next
FlowNode   -> rule, next
BranchNode -> branches
DNode      -> defaultBranch
LNode      -> rules
```

`TreeNode.validate()` 执行结构校验：

- `TreeNode.next` 和每个 `FlowNode.rule` 必须存在
- `SNode`、`PNode` 至少包含一个分支
- `DNode` 至少包含一个条件分支，并且条件分支与默认分支合计至少形成两个结果出口
- `DNode.defaultBranch` 只能是 `ANode`、`DNode`、`PNode` 或 `SNode`
- `LNode.expr` 只能是 `&&` 或 `||`，并且至少包含两个子规则
- `HNode` 至少包含一个子规则，上下界不能同时为空，并满足 `0 <= min <= max <= rules.size()`
- 叶子规则表达式不能为空

`TreeNode.validateSize(maxDepth, maxNodes)` 使用对象身份检查整棵树，拒绝重复对象引用和循环引用。参考 Web 在服务端和编辑器中使用相同预算：

```text
最大深度  128
节点总数  2000
```

草稿保存只执行反序列化和规模校验，允许保存尚未完成的结构；发布时才执行完整结构校验、编译和引用校验。

## 5. 单向编译

```text
UI TreeNode JSON
      │ deserialize / validateSize
      ▼
   TreeNode
      │ validate / UINodeAdapter.toRule()
      ▼
   RuleNode
      │ expr / RuleDefinition(ruleType=2)
      ▼
   RuleSuite
```

`UINodeAdapter` 的当前映射：

| UI 结构 | 内核结构 |
| --- | --- |
| 单个 `ANode` | 解析 `rule.ruleExpr()` |
| 连续 `ANode.next` | 一个 `SerNode` |
| 无后继的 `CNode` | 条件规则自身 |
| 有后继的 `CNode` | `CaseNode(condition, matched)` |
| `DNode` | 按条件顺序反向嵌套 `CaseNode` |
| `SNode` | 带 `∅` 结构占位的 `SerNode` |
| `PNode` | 带 `∅` 结构占位的 `ParNode` |

编译只读取执行语义：

- `name`、选择状态、折叠状态和节点坐标不进入执行树
- `RNode.expr` 保存稳定规则 ID，不复制后台 JavaScript 表达式
- `DNode` 按列表顺序检查条件，条件没有命中流程时以 `∅` 表示命中后停止
- 业务场景引用以 `f<id>` 存在普通动作规则引用中，不引入专用调用节点
- 不提供从执行树返回 UI AST 的逆向转换

## 6. 画布与规则弹窗

主画布只展开 Flow 递归：

- `SNode`、`PNode`、`DNode` 分别显示为“串”“并”“分”
- `CNode` 与其规则子树合并为一个条件节点
- 条件命中流程沿 `CNode.next` 在主画布继续展开
- 节点位置、折叠、缩放和连线方向只服务阅读
- 主画布和规则弹窗只允许同一父节点、同一有序列表中的兄弟重排

双击条件节点或点击“查看规则”打开规则弹窗：

- 弹窗只编辑纯 Rule 子树，不导航 `CNode.next`
- 一条引用使用原子条件，多条引用可以组合为与或
- 原子条件支持模板参数和取反
- 已有 `HNode` 可以显示和保存，当前与或转换入口不新建 `some`
- “保存”提交当前规则子树，“取消”或 Esc 恢复打开弹窗时的快照

所有节点的可选展示名称统一使用 `name`。条件画布名称来自 `CNode.name`，内部规则名称来自 `CNode.rule.name`，两者互不覆盖。

## 7. 引用与版本

参考 Web 在发布时校验引用：

- 动作节点只能引用动作类型原子规则、已发布业务场景或内置 `∅`
- 条件节点只能引用条件类型原子规则或允许的内置条件
- 业务引用必须存在、可用并与当前场景属于同一命名空间

每个业务场景拥有稳定 `flowId` 和递增版本：

- 新建场景生成版本 1 的草稿
- 草稿可以宽松保存
- 发布执行严格树编译和引用校验
- 发布成功后，原当前发布版本转为历史版本，新版本成为当前发布版本
- 发布、历史和停用版本只读
- 修改只读版本时，先以选定版本为基础创建新草稿
- 发布或保存失败时不部分替换当前树

发布流程在事务提交前构造候选 `RuleSuite`，提交后替换当前命名空间的运行套件。Core 本身不保存草稿、版本和发布状态。

## 8. 页面入口

- `/`：产品首页
- `/namespaces`：命名空间选择与管理
- `/scenes`：业务场景与版本
- `/rules`：原子规则库
- `/udfs`：JavaScript UDF 注册中心
- `/flow/{flowId}`：指定业务场景的规则树编辑器
- `/ui/*.html`：Spring Boot 静态资源入口
