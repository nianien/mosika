# 开发与运行

## 环境要求

- JDK 21
- Maven 3.9 或兼容版本
- 启动脚本还会使用 `curl` 和系统端口查询工具，可执行 `./scripts/mosika.sh doctor` 检查环境

普通 JDK 21 可以运行 GraalJS Polyglot。高频 JavaScript 场景可根据部署环境评估 GraalVM，但这不是构建项目的前置条件。

## 模块结构

| 路径 | 职责 |
| --- | --- |
| `mosika-core/` | DSL、执行树、执行上下文、结果模型、UDF 和 RuleFlow |
| `mosika-ui/` | 可序列化 UI AST，以及 UI 树到内核 `RuleNode` 的单向编译 |
| `mosika-web/` | Spring Boot 管理服务、SQLite 持久化、REST 和静态编辑器 |
| `scripts/` | Web 服务构建、启停、状态和日志脚本 |
| `docs/` | 项目详细文档与文档图片 |

ANTLR 语法位于 `mosika-core/src/main/antlr4/Rule.g4`。不要修改 `target/generated-sources/` 中的生成代码。

## 构建与测试

完整验证：

```bash
mvn clean test
```

按模块验证：

```bash
mvn -pl mosika-core test
mvn -pl mosika-ui -am test
mvn -pl mosika-web -am test
```

生成全部制品：

```bash
mvn clean package
```

修改解析、执行、并发上下文或 UI 树转换时，应增加对应的 JUnit 5 回归测试。仅修改文档时无需执行全量测试，但必须检查链接和 Markdown/SVG 文件完整性。

## Web 服务

统一通过以下脚本操作：

```bash
./scripts/mosika.sh doctor
./scripts/mosika.sh build
./scripts/mosika.sh start
./scripts/mosika.sh status
./scripts/mosika.sh logs
./scripts/mosika.sh restart
./scripts/mosika.sh stop
```

开发模式以前台方式运行：

```bash
./scripts/mosika.sh dev
```

默认访问地址：

- 规则流列表：<http://127.0.0.1:8080/>
- 原子规则库：<http://127.0.0.1:8080/rules>
- 规则流画布：`http://127.0.0.1:8080/flow/{id}`
- 健康检查：<http://127.0.0.1:8080/api/health>

Web 页面源码位于 `mosika-web/src/main/resources/static/ui/`。Spring Boot 使用标准静态资源规则把它发布为 `/ui/**`，`WebConfig` 只负责简洁页面路由的转发。

## 运行状态与配置

状态文件和日志默认写入 `${TMPDIR:-/tmp}/mosika/`，不会写入仓库。SQLite 属于 Web 参考实现，默认位于 `mosika-web/data/mosika.db`；仓库跟踪一份可直接试用的演示数据库，但不跟踪 WAL、SHM 和 journal 等运行时文件。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `MOSIKA_PORT` | `8080` | 服务端口 |
| `MOSIKA_SERVER_ADDRESS` | `127.0.0.1` | 监听地址 |
| `MOSIKA_DB_PATH` | `mosika-web/data/mosika.db` | SQLite 数据库路径 |
| `MOSIKA_RUN_DIR` | `${TMPDIR:-/tmp}/mosika` | 状态与日志目录 |
| `MOSIKA_START_TIMEOUT` | `60` | 启动检查超时秒数 |
| `MOSIKA_STOP_TIMEOUT` | `15` | 停止等待秒数 |
| `MOSIKA_JAVA_OPTS` | 空 | 额外 JVM 参数 |

完整参数以 `./scripts/mosika.sh help` 的当前输出为准。

## 变更验证边界

- Core：沿 `Rule.g4 → DefaultRuleVisitor → RuleNode.eval() → 测试` 验证语义。
- UI AST：检查 `toRule()`、`TreeNode.visit()`、`NodeTypeResolver` 和 JSON 往返。
- Web：检查控制器、持久化、静态资源路由，并执行 `mvn -pl mosika-web -am test`。
- 浏览器交互变更不能只用 Java 测试证明；需要在真实页面验证选择、弹窗、拖拽、保存和错误态。
